# Airway — test and build contract

Before each push:

```sh
npm ci
npm run test:fast     # typecheck + every headless unit test, ends with test:arch (~1.5–2 min: 122 steps in parallel, 97–111 s with 4 jobs on 4 vCPU, 7 Nov 2026)
npm run build
```

`npm run test:ci` runs `test:fast`, the build and every browser/perf/screenshot suite: 101 steps, about 1.5–2 hours
([night-40a] 80-step run on 7 Nov 2026, 4 vCPU, another agent's browser suites on the same machine: 6 637 s; the
slowest steps were `store:shots` ~26–30 min, `ui:matrix` 13 min, `shots` 9 min, `test:e2e:screen-audit:stub` 6.5 min, `test:e2e:pseudo-locale`,
`test:e2e:text-scale-150`, `test:e2e:gameover-contracts`, `test:hud-targets` and `test:perf-scene` 2–4 min each). Both suites use
`scripts/run-suite.mjs`: every step runs even after a failure, one `PASS|FAIL <step> <seconds> <SUMMARY>` line is
printed per step in step-list order (with the output tail on failure), and the run ends with
`SUMMARY <suite> seed=0xA1A1 steps=N passed=N failed=N durationS=N jobs=N [failing=…]` and a nonzero exit if any step
failed. Add a new fast test by appending its script name to the `test:fast` step list in `package.json` (before
`test:arch`).

[night-33b] D-289: the runner starts steps in a pool of `jobs` processes and buffers their output, so the printed
lines and the SUMMARY are the same as one by one; only the seconds per step grow under load. `jobs` = CPUs, at most
8 and at most one per 1.5 GiB of RAM; `AW_JOBS=N` changes the default, `npm run test:fast -- --jobs=N` overrides both,
and `--jobs=1` is the old sequential run (list order, each line as soon as its step ends). `test:ci` passes
`--jobs=1`: its browser steps launch Vite and Chromium and stay one at a time; only its first step, `test:fast`, runs
in parallel. With `jobs` > 1 the pool starts the steps that were slowest last time first (durations cached in
`node_modules/.cache/run-suite/`). A new test runs in parallel with the others, so it must write only to its own
`mkdtemp` folder, never to a fixed path, port or shared file. A step that cannot share the machine (a fixed
port, a shared file, Vite/Chromium, a wall-clock budget that assumes an idle CPU) goes into `SERIAL_STEPS` in
`scripts/run-suite.mjs`: it starts on an idle pool and nothing runs beside it. Today: `test:overlay-layout`
(placement under 1 ms per frame) and `test:replay-cost` (replay within 600 ms per game week). [night-52a] D-311: under V8 coverage (`coverage:fast`) their budgets print INFO instead of failing.

## Rules for tests

- Fixed seed (`0xA1A1` where no gameplay seed is needed), nonzero exit on failure, exactly one final
  `SUMMARY <name> seed=… passed=N failed=N` line, an npm script `test:*` / `perf:*` / `shots*`, and one row below.
- Node tests use Node 22+ type stripping (`node --experimental-strip-types`); sources import `*.ts` so the same modules
  run under Node and Vite (`allowImportingTsExtensions` + `noEmit`).
- Browser suites use the **environment's** Playwright 1.63 + Chromium (CI: `npm install --no-save playwright@1.63.0`);
  neither is an npm dependency. They start a disposable Vite dev server (`AIRWAY_E2E_URL` reuses a running one) and
  launch Chromium with `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist`
  (`scripts/lib/harness.mjs`). `CHROMIUM_PATH` overrides the browser binary. SwiftShader FPS is never device evidence.
- Fail closed (D-37): a missing screen, adapter or fixture is a FAIL, never a skipped pass. Harness-only fixtures
  report `mode=fixture` and write only to ignored folders.

## Commands

Suite column: “fast” = a step of `test:fast`; “ci” = a step of `test:ci` that is not in `test:fast`; “manual” = a test or
capture run by hand; “tool” = a generator or helper. `test:doc-ids` enforces the column, a row for every `test:ci` step
and every `test:*`/`perf:*` script, and that every row names an existing script.

[night-40a] Times: “fast” rows were measured with `npm run test:fast -- --jobs=1` and “ci” rows in one
`npm run test:ci` run, both on 7 Nov 2026 in a 4 vCPU container (SwiftShader) while another agent's browser suites ran
on the same machine (load average 4–18), so they are upper bounds; browser steps late in the run were up to 3× slower
than their earlier figures. Steps marked “:stub” run on the DEV stub world (no WebGL); every other browser step loads
the real globe.
